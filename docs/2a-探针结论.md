# 2a DOM 探针结论（2026-10-19 晚）

> 探针方式：APP v0.1.3 开启 WebView 调试 → adb forward → CDP `Runtime.evaluate` 只读采样
> 样本：真实会话页 `/remote/v4`，任务列表视图（3 工作区 · 5 任务）
> 探针脚本：`tools/probe.mjs` + `tools/probe-expression.js`（可随时重跑）

## 结论：GO。任务状态可稳定识别，质量超预期

| 问题 | 答案 | 证据 |
|---|---|---|
| 任务卡有稳定标识吗 | **有，官方测试钩子** | 每张卡是 `<button data-testid="task-item-sess_<uuid>"`，uuid 即会话 ID，可做 diff 主键 |
| 状态怎么识别 | 双保险 | ① 徽章元素**直接持有**文本节点（运行中/已完成/错误）② Tailwind 语义类：运行中=`bg-accent border-brand/40`，已完成=`bg-success border-success/40` |
| 卡片文本可提取吗 | 可 | `textContent` = 任务名+相对时间+状态（如 "泠娜项目10小时已完成"） |
| 流式输出会打爆观察器吗 | 未知但影响可控 | 列表视图 `mutationsIn5s=0`（完全静态，WS 驱动更新）；会话详情页的流式频度未测，debounce 2s 可兜底 |
| 虚拟滚动回收风险 | 低 | 246 个元素，5 任务全量渲染，无虚拟化迹象；任务数多了以后需复查 |
| SPA 路由切换问题 | 存在 | React SPA（`#root`），路由切换不触发 `onPageFinished`；注入需一次注入+自检存活+重注入 |
| iframe/Shadow DOM | 无 | 全部在主文档 |
| 额外发现 | 页面挂有阿里云盾验证码容器（隐藏），与通知无关 |

## 设计修正

- **选择器策略定稿**：`[data-testid^="task-item-"]` 为主键源，状态从徽章 ownText 判定，类名做辅助校验。data-testid 语义化且是官方测试钩子，比 Tailwind 类名稳定
- **通知 diff 逻辑**：快照 `{uuid → 状态}`，MutationObserver 触发后对比：新增任务 / 状态迁移（→已完成、→错误、→运行中）分别映射通知渠道
- **注入时机**：`onPageStarted` 注入 + MutationObserver 等待 `[data-testid^="task-item-"]` 出现再开始快照；每次路由变化自检 observer 存活
- **探针插曲（方法论）**：第一版探针用 `children.length===0` 判"叶子"全数打空——徽章内含 svg 图标。"叶子元素"假设不可靠，要按"直接持有的文本节点"判定
